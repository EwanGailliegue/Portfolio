Algorithmique

Optimisation d'itinéraire TSP via OSRM

Problème & solution

Lors de l'ouverture de la carte, l'application doit calculer l'ordre de passage optimal entre N dépôts restants — un problème NP-difficile (TSP). Plutôt qu'une approche naïve O(n!), l'app délègue la résolution à l'API OSRM /trip/v1/driving/ qui implémente une heuristique farthest insertion + optimisation locale sur le réseau routier réel.

O(n!)Naïf évité
~25Waypoints max

02

Rendu Flutter

Widgets const & modèles immuables

Principe

L'utilisation systématique de const permet à Flutter d'éviter la reconstruction des sous-arbres de widgets inchangés lors d'un setState. Les modèles déclarent tous leurs champs en final, garantissant l'immuabilité et simplifiant les comparaisons lors des rebuilds.

577Occurrences const

Exemple — modèle immuable

class ClientDelivery { final String id; final DateTime scheduledDate; final String status; const ClientDelivery({ required this.id, required this.scheduledDate, required this.status, }); }
03

Rendu de listes

Lazy rendering avec ListView.separated

Principe

Les listes utilisent ListView.separated() avec un itemBuilder, construisant les éléments à la demande plutôt que tous d'un coup. Pour les petites listes connues, le spread operator est préféré à une boucle avec add().

Lazy renderingitemBuilderSpread operator

Exemple

ListView.separated( itemCount: filtered.length, separatorBuilder: (_, __) => const SizedBox(height: 8), itemBuilder: (ctx, i) => _HistoryTile( delivery: filtered[i], onTap: ..., ), )

Sécurité & performance

Injection du token JWT à la demande

Principe

Le token d'authentification n'est lu depuis le stockage sécurisé qu'au moment de la requête, évitant de le maintenir en mémoire vive entre les appels.

flutter_secure_storageLazy evaluationKeychain / Keystore

Implémentation

Future<Map<String, String>> _headers({bool auth = true}) async { final h = { 'Accept': 'application/json', }; if (auth) { // lecture lazy depuis le keychain final token = await tokenProvider(); if (token != null) h['Authorization'] = 'Bearer $token'; } return h; }

Architecture & qualité

Séparation UI / données & thème centralisé

Principes appliqués

  • Feature-first — chaque fonctionnalité isolée dans son propre dossier
  • Couche services — l'UI ne manipule jamais de JSON brut
  • Thème centralisé — couleurs en static const dans AppColors
  • Navigation propre — pushReplacement après connexion, pushAndRemoveUntil à la déconnexion
  • flutter_lints — détection statique des anti-patterns à la compilation
